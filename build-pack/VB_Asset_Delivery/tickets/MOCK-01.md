## Creative and technical requirements
1. Use Windows-95-inspired window chrome around a green felt table; two player piles, central face-up cards, count labels, Deal and Watch buttons, and a speed slider.
2. Draw all card faces and backs with the shared SVG primitives; no commercial card art or copied Solitaire sprites.
3. Use one internally consistent in-progress state: Player1 25, Player2 25, pot2. Any card labels must correspond to the displayed cards.
4. Include the source’s “This is what you’d build next.” label. Metadata must explicitly say conceptual GUI mockup; it is not an implemented VB4 application.
5. Provide a clean table state and a clearly labeled annotated state. Do not add account screens, settings menus, or unsupported game features.
