# H06 — Narration recording or authorized TTS

**Original Tier 3 source:** ASSET_PLAN.md:141

**Status:** Handoff planned; no gated action performed.

## Purpose
Create the narration from an approved script version, using the user’s recording or a specifically authorized TTS voice/service.

## Inputs
Immutable original script plus producer-approved revision ledger; pronunciation notes and section map

## Agent-preparable work and handoff steps
1. Resolve high-impact editorial gates before final narration. Do not simply record unsupported claims and hope later visuals conceal them.
2. Record section-by-section files with consistent voice/pace. Prepare pronunciation notes for VB identifiers and historical names without silently rewriting source text.
3. No TTS provider, voice identity, key, budget, or consent was supplied. User chooses and authorizes them; credentials stay in secure environment variables or the provider UI, not Markdown.
4. Preserve original audio, approved text version, take/section mapping, and generation settings where used. Return real durations to the editor.

## Actual human/capability boundary
Approved narration copy, voice/service choice, any required consent, account/key access, and purchase decision.

Original “human-only” wording is preserved as the plan's boundary, not a claim that no authorized future agent can operate the tool. First establish available capabilities and real permission; do not bypass missing access or claim work happened.

## Expected return package
- Actual narration audio plus section/text/version mapping and recorded durations.
- No claim of voice generation or recording without real files and playback review.

## Acceptance and stop rules
- [ ] Required user decisions and permissions are documented.
- [ ] Returned paths refer to real files; source/rights/versions and review results are recorded.
- [ ] No secret, password, token, or unapproved paid action appears in the pack.
- [ ] This handoff is marked complete only for the actual action performed, not for a proposed workaround.

If blocked, record the exact missing file, account permission, decision, or local capability. Do not request the original attachments again; they are already in sources/.
